The Classes lesson covered the basics. Python's object model goes much further: special ("dunder") methods let your objects work with built-in syntax, abstract base classes define contracts, and dataclasses remove boilerplate.

## Dunder methods: making objects feel built-in

```python
from functools import total_ordering

@total_ordering
class Money:
    def __init__(self, amount: float, currency: str = "INR"):
        self.amount = round(amount, 2)
        self.currency = currency

    def __repr__(self) -> str:                 # for developers (debugging, logs)
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self) -> str:                  # for users (print, f-strings)
        return f"{self.currency} {self.amount:,.2f}"

    def __add__(self, other: "Money") -> "Money":
        if other.currency != self.currency:
            raise ValueError("Currency mismatch")
        return Money(self.amount + other.amount, self.currency)

    def __eq__(self, other: object) -> bool:
        return isinstance(other, Money) and (self.amount, self.currency) == (other.amount, other.currency)

    def __lt__(self, other: "Money") -> bool:
        return self.amount < other.amount

    def __hash__(self) -> int:
        return hash((self.amount, self.currency))

    def __bool__(self) -> bool:
        return self.amount != 0

total = Money(499) + Money(1299.5)
print(total)                       # INR 1,798.50
print(repr(total))                 # Money(1798.5, 'INR')
print(sorted([Money(50), Money(10)]))
print(Money(10) <= Money(20))      # True — generated by @total_ordering
```

Common dunder methods:

| Method | Enables |
| --- | --- |
| `__repr__`, `__str__` | `repr(x)`, `print(x)` |
| `__eq__`, `__lt__`, … | `==`, `<`, sorting |
| `__hash__` | Use as dict key / in sets (define with `__eq__`) |
| `__len__`, `__getitem__`, `__contains__`, `__iter__` | `len(x)`, `x[i]`, `in`, `for` loops |
| `__add__`, `__mul__`, … | Arithmetic operators |
| `__call__` | Calling an instance like a function |
| `__enter__`, `__exit__` | `with` statements (next lessons) |

## Container-like classes

```python
class Playlist:
    def __init__(self, name, songs=None):
        self.name = name
        self._songs = list(songs or [])

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]          # also enables slicing and iteration

    def __contains__(self, song):
        return song in self._songs

p = Playlist("Focus", ["Lo-fi 1", "Rain", "Piano"])
print(len(p), p[0], p[1:], "Rain" in p)
for song in p:
    print(song)
```

## Properties

Expose computed or validated attributes with attribute syntax:

```python
class Product:
    def __init__(self, name: str, price: float):
        self.name = name
        self.price = price                 # goes through the setter

    @property
    def price(self) -> float:
        return self._price

    @price.setter
    def price(self, value: float) -> None:
        if value < 0:
            raise ValueError("Price cannot be negative")
        self._price = value

    @property
    def price_with_gst(self) -> float:
        return round(self._price * 1.18, 2)

p = Product("Mouse", 799)
print(p.price_with_gst)   # 942.82
```

## Class methods and static methods

```python
from datetime import date

class Employee:
    company = "Acme"                       # class attribute (shared)

    def __init__(self, name: str, joined: date):
        self.name = name
        self.joined = joined

    @classmethod
    def from_record(cls, record: str) -> "Employee":   # alternative constructor
        name, joined = record.split(",")
        return cls(name, date.fromisoformat(joined))

    @staticmethod
    def is_valid_name(name: str) -> bool:             # utility; no access to cls or self
        return name.replace(" ", "").isalpha()

e = Employee.from_record("Asha Patil,2021-04-01")
print(e.name, e.joined.year, Employee.is_valid_name("Asha Patil"))
```

## Abstract base classes

Define a contract that subclasses must implement:

```python
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    @abstractmethod
    def charge(self, amount: float, token: str) -> str: ...

    def refund(self, charge_id: str) -> None:
        raise NotImplementedError("Refunds not supported")

class FakeGateway(PaymentGateway):
    def charge(self, amount: float, token: str) -> str:
        return f"ch_{token}_{int(amount)}"

gateway = FakeGateway()
print(gateway.charge(499, "tok123"))
# PaymentGateway() would raise TypeError: can't instantiate abstract class
```

For duck-typed interfaces without inheritance, `typing.Protocol` (see the type hints lesson) is often more flexible.

## Inheritance and `super()`

```python
class Notification:
    def __init__(self, recipient: str):
        self.recipient = recipient

    def send(self, message: str) -> str:
        return f"to {self.recipient}: {message}"

class SmsNotification(Notification):
    def send(self, message: str) -> str:
        return "SMS " + super().send(message[:160])   # reuse the parent implementation

print(SmsNotification("+91 98765 43210").send("Your order has shipped"))
```

Python supports multiple inheritance; the **method resolution order** (`Cls.__mro__`) decides which implementation wins. Use multiple inheritance mainly for small "mixin" classes, and prefer composition for everything else.

## Dataclasses revisited

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True, order=True)
class Coordinate:
    lat: float
    lng: float

@dataclass
class Order:
    id: str
    items: list[str] = field(default_factory=list)   # never use a mutable default directly
    total: float = 0.0

    def __post_init__(self):
        if self.total < 0:
            raise ValueError("total must be non-negative")

office = Coordinate(18.52, 73.85)
print(office)                      # Coordinate(lat=18.52, lng=73.85)
print(Order("SO-1").items)         # []
```

- `frozen=True` makes instances immutable (and hashable).
- `slots=True` reduces memory usage and speeds up attribute access.
- `order=True` generates comparison methods.
